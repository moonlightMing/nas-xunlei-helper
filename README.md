# NAS 迅雷助手

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

把下载链接（`thunder://`、`magnet:`、`ed2k:`、`http(s)://`）一键发送到 NAS 迅雷。

- 适配后端：[cnk3x/xunlei](https://github.com/cnk3x/xunlei)（群晖套件版 `pan-xunlei-com`）
- 灵感来源：[Soraika/nas-thunder-helper](https://github.com/Soraika/nas-thunder-helper)
- 技术栈：[WXT](https://wxt.dev) + [Vue 3](https://vuejs.org) + TypeScript + [Ant Design Vue](https://antdv.com)
- 项目地址：[github.com/moonlightMing/nas-xunlei-helper](https://github.com/moonlightMing/nas-xunlei-helper)

## 功能

- **控制面板（设置页）**
  - NAS 迅雷地址：带格式校验
  - 默认下载位置：可手动填写，也可从迅雷目录树中选择；发送时自动预选该目录
  - **发送通道**：
    - **页面自动化（默认）**——打开迅雷页面模拟点击，兼容性最好，支持「确认后下载」
    - **接口直连**——不打开迅雷页面、不抢焦点，直接调用套件自身的 `drive/v1` 接口建任务；磁力/种子同样走番号匹配勾选目标文件；此通道下「下载模式 / 发送前刷新」不生效
    - **重复资源防呆**（接口直连）——发送前比对 NAS 上已有任务的资源标识，命中同一资源时先拦下并点名，不会静默覆盖旧任务记录；确认要重发可点「仍然发送」
  - 下载模式：
    - **立即下载**——自动解析并点击「立即下载」，全程无需打开迅雷页面操作
    - **确认后下载**——自动解析后停留在迅雷下载确认框，由你编辑文件名、保存位置后手动确认
  - 发送前刷新开关：默认开启，保证干净状态；关闭可减少对当前页面的打断
  - **测试连接**：检查地址格式、页面可达、登录状态、下载面板、默认目录是否存在且可写
  - **通知与任务监控**：发送成功/失败、路径未生效、下载失败/完成分别可开关
  - **发送记录**：最近 50 条，失败可一键重试，可清空
  - **番号匹配**（独立 tab）：磁力/种子解析后，按番号从文件树中自动勾选目标视频；支持文件类型、最小大小、排除关键词、排序与每任务上限。默认严格模式，未匹配时暂停不下载，可切换回退；**页面自动化与接口直连两条通道共用同一套匹配规则**；提供只读规则预览（粘贴文件名、本地文件夹、当前迅雷弹窗），不上传任何文件
  - 一键打开迅雷页面、恢复默认设置
- **右键菜单发送**：链接、选中文本、视频/音频元素 →「发送到 NAS 迅雷」；选中多个链接时会全部提取
- **popup 双页**：「下载任务」页实时显示进度、速度、已下/总大小与 NAS 路径，可暂停/继续/删除；「发送链接」页支持多行或空格分隔、自动去重、协议校验、Ctrl / ⌘ + Enter 发送
- **可操作桌面通知**：失败通知可打开设置/迅雷并重试；下载失败/完成可按开关通知；点击通知直达迅雷页
- **下载任务监控**：发送后每分钟检查任务状态，失败默认通知、完成默认不通知；需保持迅雷页面打开

## 通知与任务监控

- **发送结果**：发送失败默认通知，发送成功默认不通知；可在设置页单独开启。保存路径未生效时默认提醒。
- **番号匹配暂停**：严格模式下有任务未识别/文件树未就绪时不点击下载，发送「已暂停」通知，按钮可打开迅雷或设置；不启动任务监控。
- **任务监控**：发送前记录任务 id 基线，发送后每分钟读取迅雷页面里的任务状态。任务失败默认通知，任务完成默认不通知；可在设置页调整。
- **监控边界**：依赖迅雷页面保持打开，插件不会主动重开页面；关闭页面、连续读取失败或超过 24 小时后停止，并在「发送记录」中写明原因。
- **实现方式**：只读复用迅雷面板自身的 Vuex 状态和 `drive/getTask` 查询，不新增后端，也不自行调用 NAS HTTP 接口。

## 权限说明

- `storage`：保存设置、发送记录与任务监控状态（仅本机）
- `contextMenus`：右键菜单
- `tabs`：查找、打开和聚焦迅雷页面
- `scripting`：向已登录的迅雷页面注入自动化脚本
- `notifications`：发送结果与下载任务结果通知
- `alarms`：任务监控的每分钟检查
- `host_permissions`：NAS 地址由用户动态配置，因此放行 http/https；扩展只用它访问用户配置的迅雷页面

## 环境要求

- 支持 Manifest V3 的浏览器：
  - Google Chrome / Microsoft Edge
  - Cent Browser（百分浏览器）**5.x 及以上**（Chromium 118/132 内核）；4.x（Chromium 80）无法加载
- NAS 已安装并运行 [cnk3x/xunlei](https://github.com/cnk3x/xunlei)（群晖套件版 `pan-xunlei-com`），且你已在浏览器中登录过其 Web 页面
- 从源码构建或本地调试还需 Node.js **>= 22** 与 pnpm，见[开发文档](docs/DEVELOPMENT.md)

## 安装

### 日常浏览器

1. `pnpm build`
2. 打开 `chrome://extensions`，开启「开发者模式」
3. 「加载已解压的扩展程序」选择 `.output/chrome-mv3`
4. 打开扩展设置页，填入 NAS 迅雷地址（如 `http://192.168.5.2:2345/webman/3rdparty/pan-xunlei-com/index.cgi/#/home`）
5. **先在浏览器中打开一次迅雷页面并登录**（本插件复用已登录会话，不管理凭证）
6. 在任意网页右键链接「发送到 NAS 迅雷」，或在 popup 中粘贴链接发送

### 打包分发

`pnpm zip` 生成 `.output/nas-xunlei-helper-<version>-chrome.zip`。解压后按上文加载，或提交到浏览器扩展商店。

> 安装仅发生在本地浏览器；NAS 不需要安装、上传或重启任何东西。

开发调试（独立 profile、扩展重载、验收清单）见[开发文档](docs/DEVELOPMENT.md#调试部署)。

## 常见问题

开发与调试问题见[开发文档](docs/DEVELOPMENT.md#开发排障)。

**发送时提示未配置地址或地址非法**
到扩展设置页填写以 `http://` 或 `https://` 开头的完整迅雷 Web 地址并保存。

**发送失败时如何排查**
通知或 popup 会给出具体原因和下一步：

- **地址未配置/不正确**：到设置页修正地址
- **无法访问 NAS**：确认 NAS 在线、端口或反向代理地址正确
- **需要登录**：点击「打开迅雷页面」完成登录后重试
- **页面不是迅雷下载面板 / 面板未就绪**：确认地址指向迅雷套件页面；套件升级后可能需要适配 [utils/xunleiAutomation.ts](utils/xunleiAutomation.ts) 中的选择器
- **解析失败 / 解析超时**：确认链接有效；无效链接会在解析阶段直接报错
- **迅雷页面已关闭**：重新发送

**番号匹配为什么整单暂停了？**
严格模式下只要有一个任务没识别出番号、文件树未就绪或没有符合类型/大小的文件，就不会点「立即下载」，以避免误下广告。打开迅雷页面手动检查勾选，或到「番号匹配」tab 补充番号/放宽类型/关闭严格模式后重试。

**番号匹配置了排序，为什么迅雷文件列表顺序没变？**
迅雷弹窗本身不支持排序；插件的排序只决定「每个任务最多保留 N 个」时保留哪些匹配文件，以及预览表的顺序，不会重排界面。

**直链任务没有走番号匹配**
这是预期行为。番号匹配只作用于磁力/种子解析出的 BT 文件树；普通 http(s)/thunder 直链没有文件树，会按原流程发送。

**提示「已阻止重复发送」是什么意思？**
NAS 上已经有一个指向同一资源的下载任务。迅雷在这种情况下重新添加，**如果原任务已经解析完成，会顶掉原来的任务记录**——已下载好的文件不会丢，但旧任务从列表里消失，新任务还会被放到 `名称(1)`、`(2)` 这样的新目录。因为接口直连不打开迅雷页面、你来不及看见这个后果，所以插件默认拦一次。确实要重发（比如想换勾选的文件或换保存目录），点「仍然发送」并确认即可；想保留原任务记录就不用再发。

**任务监控没有完成通知？**
下载完成通知默认关闭，请在设置页开启；同时需要保持迅雷页面打开。监控结果也会写入「发送记录」，可随时查看。

**通知没有按钮或不能常驻？**
不同操作系统对通知按钮、常驻显示的支持不同，这是尽力而为的能力；popup 内联结果和「发送记录」始终保留完整信息。

**点击重试提示上次发送记录已过期**
重试依赖最近 30 分钟内的发送记录；过期后请重新粘贴链接发送。

**关闭迅雷页面后任务监控停止**
任务监控只读复用迅雷页面的前端状态，不会主动重开页面；重新打开并再次发送即可恢复监控。

## 已知限制

- **默认下载位置只支持已存在的目录**：插件按迅雷面板显示的路径逐级查找目录并预选，不会自动创建目录；路径不存在、不在可下载目录范围内或不可写时，会回退到迅雷当前目录并在通知中说明原因。「确认后下载」模式仍可手动选择路径。
- **任务监控依赖迅雷页面保持打开**：插件不会主动重开页面；页面关闭、连续读取失败、离开配置地址或超过 24 小时后停止监控，并在发送记录中写明原因。浏览器休眠、页面被冻结时监控可能延迟。
- **任务监控依赖迅雷 Vuex 状态**：读取 `drive.all/tasks/tasksDone` 并复用面板自身的 `drive/getTask`；迅雷大版本更新若改动该结构，需要适配 [utils/xunleiAutomation.ts](utils/xunleiAutomation.ts)。任务错误详情可能无法读取，此时只保证失败状态和任务名。
- **路径预选依赖迅雷面板的前端状态**（Vuex 中的 `treeNodeId/treeNodePath`）；迅雷大版本更新若改动该结构，需要适配 [utils/xunleiAutomation.ts](utils/xunleiAutomation.ts)。
- **番号匹配依赖迅雷文件树组件**：通过页面 Vue 组件的 `setCheckedKeys` 应用勾选；迅雷大版本更新若改动组件结构/方法名，会暂停并提示手动处理，不会在不确认的情况下点击下载。匹配逻辑只用 xeyes 的文件名规则做本地识别，不引入模型、不请求外部服务。
- **番号匹配排序不改变迅雷界面**：仅用于选择保留哪些文件；设置每任务上限可能漏掉分集，默认 0（不限）。
- **番号匹配只处理 BT 文件树**：直链任务跳过；页面自动化模式下多任务严格模式整单暂停（接口直连按链接独立暂停）。手动番号/关键词仅保存在本机 `storage.local`，历史只记录计数和少量摘要，不保存完整文件列表。
- **接口直连依赖套件私有接口**：`drive/v1` 契约实测于 [cnk3x/xunlei](https://github.com/cnk3x/xunlei) v3.23.5，套件升级后可能变化；取不到令牌或接口报错时会明确失败并提示切回页面自动化，不会继续建任务。
- **接口直连不启动页面任务监控**：该通道不打开迅雷页面，因此原有的每分钟任务监控不生效，下载状态请直接在 popup「下载任务」页查看；通知仍覆盖发送结果与番号匹配暂停。
- **接口直连没有「确认后下载」**：接口层没有迅雷确认框，任务一律直接开始；需要人工确认文件名或路径时请用页面自动化通道。
- **DOM 自动化依赖 [cnk3x/xunlei](https://github.com/cnk3x/xunlei) 的页面结构**，迅雷或套件大版本更新后选择器可能需要适配。
- **通知按钮/常驻显示是尽力而为**：不同平台支持度不同；即使按钮不可用，popup 内联结果和发送记录仍保留完整信息。
- **不自动重试点击步骤**：新建任务、填链接、点击立即下载都有副作用，自动重试可能重复建任务；请使用失败通知/记录里的「重试」整链重跑。
- **发送记录保存在本机**：包含链接文本，提供清空按钮，不跨设备同步。

# NAS 迅雷助手

[![GitHub](https://img.shields.io/badge/GitHub-moonlightMing%2Fnas--xunlei--helper-181717?logo=github)](https://github.com/moonlightMing/nas-xunlei-helper)

[![Manifest V3](https://img.shields.io/badge/Manifest-V3-brightgreen.svg)](https://developer.chrome.com/docs/extensions/develop/migrate)
[![WXT](https://img.shields.io/badge/WXT-0.21-2c3e50.svg)](https://wxt.dev)

浏览器扩展：把网页里的下载链接（`thunder://`、`magnet:`、`ed2k:`、`http(s)://`）一键发送到 NAS 迅雷远程下载。

**适配后端**：[cnk3x/xunlei](https://github.com/cnk3x/xunlei) —— 从迅雷群晖套件提取的迅雷远程下载服务（群晖套件版 `pan-xunlei-com`），接口契约实测于 3.x（v3.23.5）。

**灵感来源**：[Soraika/nas-thunder-helper](https://github.com/Soraika/nas-thunder-helper)。本项目在其页面自动化思路的基础上，用 [WXT](https://wxt.dev) + [Vue 3](https://vuejs.org) + TypeScript + [Ant Design Vue](https://antdv.com) 重写，并扩展出接口直连、番号匹配与任务管理能力。

## 功能

- **控制面板（设置页）**
  - NAS 迅雷地址：带格式校验
  - 默认下载位置：可手动填写，也可从迅雷目录树中选择；发送时自动预选该目录
  - **发送通道**：
    - **页面自动化（默认）**——打开迅雷页面模拟点击，兼容性最好，支持「确认后下载」
    - **接口直连**——不打开迅雷页面、不抢焦点，直接调用套件自身的 `drive/v1` 接口建任务；磁力/种子同样走番号匹配勾选目标文件；此通道下「下载模式 / 发送前刷新」不生效
    - **重复资源防呆**（接口直连）——发送前比对 NAS 上已有任务的资源标识，命中同一资源时先拦下并点名，不会静默覆盖旧任务记录；确认要重发可点「仍然发送」
  - 下载模式：
    - **立即下载**——自动解析并点击「立即下载」，全程无需打开迅雷页面操作
    - **确认后下载**——自动解析后停留在迅雷下载确认框，由你编辑文件名、保存位置后手动确认
  - 发送前刷新开关：默认开启，保证干净状态；关闭可减少对当前页面的打断
  - **测试连接**：检查地址格式、页面可达、登录状态、下载面板、默认目录是否存在且可写
  - **通知与任务监控**：发送成功/失败、路径未生效、下载失败/完成分别可开关
  - **发送记录**：最近 50 条，失败可一键重试，可清空
  - **番号匹配**（独立 tab）：磁力/种子解析后，按番号从文件树中自动勾选目标视频；支持文件类型、最小大小、排除关键词、排序与每任务上限。默认严格模式，未匹配时暂停不下载，可切换回退；**页面自动化与接口直连两条通道共用同一套匹配规则**；提供只读规则预览（粘贴文件名、本地文件夹、当前迅雷弹窗），不上传任何文件
  - 一键打开迅雷页面、恢复默认设置
- **右键菜单发送**：链接、选中文本、视频/音频元素 →「发送到 NAS 迅雷」；选中多个链接时会全部提取
- **popup 双页**：「下载任务」页实时显示进度、速度、已下/总大小与 NAS 路径，可暂停/继续/删除；「发送链接」页支持多行或空格分隔、自动去重、协议校验、Ctrl / ⌘ + Enter 发送
- **可操作桌面通知**：失败通知可打开设置/迅雷并重试；下载失败/完成可按开关通知；点击通知直达迅雷页
- **下载任务监控**：发送后每分钟检查任务状态，失败默认通知、完成默认不通知；需保持迅雷页面打开

## 工作原理

沿用原型的 **DOM 自动化** 路线：复用浏览器里已登录的迅雷 Web 会话，通过
`chrome.scripting.executeScript` 向迅雷页面注入脚本，模拟点击「新建任务 → 填链接 → 解析 → 立即下载」。
保存路径通过读取迅雷页面自身的 Vuex 状态、按路径解析出目录 ID 后预选，再交给面板原生的建任务流程；
全程复用已登录会话，无需存储账号密码，也不自行拼接建任务请求。

> 路径填写的是**迅雷面板里显示的路径**（如 `/downloads/movies`），不是 NAS 宿主机路径。
> 目录必须已在迅雷中创建；插件不会自动建目录。路径不存在或不可写时会回退到迅雷当前目录，并在通知中说明原因。

迅雷 Web UI 的关键选择器集中在 [utils/xunleiAutomation.ts](utils/xunleiAutomation.ts)，套件更新导致 DOM 变化时只需调整该文件。

番号匹配在解析结果弹窗出现后**只读**读取 BT 文件树，在本机计算匹配计划，再调用迅雷面板自身的文件树组件应用勾选；不重排界面、不自行拼接 NAS 请求。番号识别参考 xeyes 的文件名归一化规则，支持标准番号、FC2、Tokyo Hot、无码日期码、分集/字幕后缀等；排序只决定保留哪些文件（尤其配合上限），**不会改变迅雷弹窗中的文件顺序**。任务名带番号但没有任何文件命中时，视频文件按任务名整体保留；一旦有文件命中该番号，其余不带番号的文件按不匹配排除，避免误选广告或说明视频。

> 严格模式下一次发送多个任务时，只要任一任务未识别就整单暂停，因为迅雷只有一个「立即下载」按钮，无法只提交部分任务。直链任务没有 BT 文件树，会自动跳过番号匹配。

### 接口直连通道

选择「接口直连」后，插件不再打开迅雷页面，而是调用迅雷套件自身的 `drive/v1` 接口：先用 `resource/list` 解析磁力/种子得到 BT 文件树，**在同一套 `avMatch` 纯函数里算出要保留哪些文件**，再把选中序号编码成接口参数（如 `"0"`、`"0-1,3"`）随建任务请求下发，保存路径则按配置的 NAS 路径逐级解析成目录 Id。

因此这条通道下：不跳转、不抢焦点、不依赖迅雷弹窗结构；番号匹配与页面自动化完全一致，而且**每个链接是独立任务，未匹配的只暂停自己，不会连累同一批里的其它链接**。

鉴权使用套件首页下发的短期令牌（约 3 天有效），插件只在内存/会话存储里缓存它，**不接触、不保存你的迅雷账号密码**。若迅雷版本变化导致取不到令牌，会明确报错并提示切回页面自动化，不会瞎猜接口。

> 本仓库只有浏览器扩展，没有 NAS 端组件或后端服务；NAS 侧只需运行 [cnk3x/xunlei](https://github.com/cnk3x/xunlei)（群晖套件版 `pan-xunlei-com`）。

## 通知与任务监控

- **发送结果**：发送失败默认通知，发送成功默认不通知；可在设置页单独开启。保存路径未生效时默认提醒。
- **番号匹配暂停**：严格模式下有任务未识别/文件树未就绪时不点击下载，发送「已暂停」通知，按钮可打开迅雷或设置；不启动任务监控。
- **任务监控**：发送前记录任务 id 基线，发送后每分钟读取迅雷页面里的任务状态。任务失败默认通知，任务完成默认不通知；可在设置页调整。
- **监控边界**：依赖迅雷页面保持打开，插件不会主动重开页面；关闭页面、连续读取失败或超过 24 小时后停止，并在「发送记录」中写明原因。
- **实现方式**：只读复用迅雷面板自身的 Vuex 状态和 `drive/getTask` 查询，不新增后端，也不自行调用 NAS HTTP 接口。

## 权限说明

- `storage`：保存设置、发送记录与任务监控状态（仅本机）
- `contextMenus`：右键菜单
- `tabs`：查找、打开和聚焦迅雷页面
- `scripting`：向已登录的迅雷页面注入自动化脚本
- `notifications`：发送结果与下载任务结果通知
- `alarms`：任务监控的每分钟检查
- `host_permissions`：NAS 地址由用户动态配置，因此放行 http/https；扩展只用它访问用户配置的迅雷页面

## 环境要求

- Node.js **>= 22**（WXT 0.21 要求）与 pnpm
- 支持 Manifest V3 的浏览器：
  - Google Chrome / Microsoft Edge
  - Cent Browser（百分浏览器）**5.x 及以上**（Chromium 118/132 内核）；4.x（Chromium 80）无法加载
- NAS 已安装并运行 [cnk3x/xunlei](https://github.com/cnk3x/xunlei)（群晖套件版 `pan-xunlei-com`），且你已在浏览器中登录过其 Web 页面

## 部署

### 方式一：一键部署到本地调试浏览器（开发 / 验收推荐）

`scripts/deploy.mjs` 会完成「构建 → 复用或启动独立调试实例 → 重载扩展」的全流程。

| 目标浏览器 | 命令 | 调试端口 | 独立 profile |
| --- | --- | --- | --- |
| Google Chrome | `pnpm deploy` | 9223 | `.debug-profile` |
| Cent Browser | `pnpm deploy:cent` | 9224 | `.debug-profile-cent` |
| Microsoft Edge | `node scripts/deploy.mjs --browser=edge` | 9225 | `.debug-profile-edge` |

不同目标的端口与 profile 相互独立，可同时部署、共存；调试实例与日常浏览器互不影响。

#### 执行步骤

1. 安装依赖：`pnpm install`
2. （可选）先做类型检查和构建：`pnpm check`
3. 执行上表对应命令。脚本会再构建一次，因此无需提前 `pnpm build`
4. **首次部署**：若调试实例的扩展列表里没有「NAS 迅雷助手」，在它自动打开的 `chrome://extensions` 页面开启「开发者模式」，点击「加载已解压的扩展程序」，选择 `.output/chrome-mv3`；之后同一调试 profile 的部署均可全自动
5. 在扩展设置页填入 NAS 迅雷地址，并在调试实例中打开迅雷页面登录一次
6. 右键任意链接或在 popup 中发送，按 [手动测试清单](#手动测试清单) 验收

#### 脚本做了什么

1. 执行 `pnpm build`，并确认 `.output/chrome-mv3/manifest.json` 存在
2. 探测目标端口的 Chrome DevTools Protocol（CDP）：已有调试实例则复用，否则用独立 `--user-data-dir` 启动并等待端口就绪
3. 通过 `chrome://extensions` 页面的 `chrome.developerPrivate.reload()` 重载扩展
4. 若找不到扩展或重载失败：关闭调试实例、清理 Service Worker 脚本缓存，再带 `--load-extension` 重启。该回退仅对仍支持 `--load-extension` 的浏览器（Chrome for Testing、Cent 5.x 等）等效于完成部署；Chrome 137+ 正式版仍需手动加载一次

#### 环境变量

- `XUNLEI_DEBUG_PORT`：覆盖调试端口，例如 `XUNLEI_DEBUG_PORT=9333 pnpm deploy`
- `XUNLEI_DEBUG_BROWSER`：指定浏览器可执行文件路径，跳过自动探测

PowerShell 中设置方式为 `$env:XUNLEI_DEBUG_PORT=9333; pnpm deploy`。

#### 注意事项

- **Chrome 137+ 正式版忽略 `--load-extension`**：首次通常需要按上文手动「加载已解压的扩展程序」。若项目根目录存在 Chrome for Testing（`chrome/win64-<version>/chrome-win64/chrome.exe`，该目录已被 git 忽略），`pnpm deploy` 会优先使用它，可自动挂载；也可设 `XUNLEI_DEBUG_BROWSER` 指向其它 Chromium 构建
- Cent Browser 5.x（已适配 5.2.1168.83 / Chromium 132）没有该限制，首次部署通常即可自动挂载；安装在便携目录（如 `D:\Software\CentBrowser\Application\chrome.exe`）时脚本可自动探测，其它位置请设 `XUNLEI_DEBUG_BROWSER`
- 调试 profile 是项目内的独立目录且已被 git 忽略，不会污染日常浏览器，也不要提交
- 部署后如果行为仍是旧版本，按 [常见问题](#常见问题) 清理 Service Worker 脚本缓存

### 方式二：安装到日常浏览器

1. `pnpm build`
2. 打开 `chrome://extensions`，开启「开发者模式」
3. 「加载已解压的扩展程序」选择 `.output/chrome-mv3`
4. 打开扩展设置页，填入 NAS 迅雷地址（群晖套件默认形如 `http://192.168.5.2:2345/webman/3rdparty/pan-xunlei-com/index.cgi/#/home`；Docker 部署请填其 Web UI 实际地址）
5. **先在浏览器中打开一次迅雷页面并登录**（本插件复用已登录会话，不管理凭证）
6. 在任意网页右键链接「发送到 NAS 迅雷」，或在 popup 中粘贴链接发送

### 方式三：打包分发

`pnpm zip` 生成 `.output/nas-xunlei-helper-<version>-chrome.zip`。解压后按「方式二」加载，或提交到浏览器扩展商店。

> 部署仅发生在本地浏览器；NAS 不需要安装、上传或重启任何东西。

## 常见问题

**部署脚本提示未找到浏览器**
脚本未能自动探测到浏览器安装位置。设置 `XUNLEI_DEBUG_BROWSER` 指向浏览器主程序（如 `...\Application\chrome.exe`）后重试。

**调试端口等待超时**
端口可能被非调试进程占用，或浏览器启动失败。先访问 `http://127.0.0.1:<端口>/json/version` 检查；关闭遗留的调试实例，或通过 `XUNLEI_DEBUG_PORT` 换一个端口。

**调试实例里没有本扩展，或部署后仍是旧行为**
- 首次：按「执行步骤」第 4 步手动加载 `.output/chrome-mv3`
- 旧行为：Chromium 会按 profile 缓存扩展 Service Worker 的脚本字节码。完全退出调试浏览器后，删除对应 profile 下的 `Default/Service Worker/ScriptCache` 目录，再重新部署（`chrome` 目标为 `.debug-profile`，Cent 为 `.debug-profile-cent`，Edge 为 `.debug-profile-edge`）

**发送时提示未配置地址或地址非法**
到扩展设置页填写以 `http://` 或 `https://` 开头的完整迅雷 Web 地址并保存。

**发送失败时如何排查**
通知或 popup 会给出具体原因和下一步：

- **地址未配置/不正确**：到设置页修正地址
- **无法访问 NAS**：确认 NAS 在线、端口或反向代理地址正确
- **需要登录**：点击「打开迅雷页面」完成登录后重试
- **页面不是迅雷下载面板 / 面板未就绪**：确认地址指向迅雷套件页面；套件升级后可能需要适配 [utils/xunleiAutomation.ts](utils/xunleiAutomation.ts) 中的选择器
- **解析失败 / 解析超时**：确认链接有效；无效链接会在解析阶段直接报错
- **迅雷页面已关闭**：重新发送

**番号匹配为什么整单暂停了？**
严格模式下只要有一个任务没识别出番号、文件树未就绪或没有符合类型/大小的文件，就不会点「立即下载」，以避免误下广告。打开迅雷页面手动检查勾选，或到「番号匹配」tab 补充番号/放宽类型/关闭严格模式后重试。

**番号匹配置了排序，为什么迅雷文件列表顺序没变？**
迅雷弹窗本身不支持排序；插件的排序只决定「每个任务最多保留 N 个」时保留哪些匹配文件，以及预览表的顺序，不会重排界面。

**直链任务没有走番号匹配**
这是预期行为。番号匹配只作用于磁力/种子解析出的 BT 文件树；普通 http(s)/thunder 直链没有文件树，会按原流程发送。

**提示「已阻止重复发送」是什么意思？**
NAS 上已经有一个指向同一资源的下载任务。迅雷在这种情况下重新添加，**如果原任务已经解析完成，会顶掉原来的任务记录**——已下载好的文件不会丢，但旧任务从列表里消失，新任务还会被放到 `名称(1)`、`(2)` 这样的新目录。因为接口直连不打开迅雷页面、你来不及看见这个后果，所以插件默认拦一次。确实要重发（比如想换勾选的文件或换保存目录），点「仍然发送」并确认即可；想保留原任务记录就不用再发。

**任务监控没有完成通知？**
下载完成通知默认关闭，请在设置页开启；同时需要保持迅雷页面打开。监控结果也会写入「发送记录」，可随时查看。

**通知没有按钮或不能常驻？**
不同操作系统对通知按钮、常驻显示的支持不同，这是尽力而为的能力；popup 内联结果和「发送记录」始终保留完整信息。

**点击重试提示上次发送记录已过期**
重试依赖最近 30 分钟内的发送记录；过期后请重新粘贴链接发送。

**关闭迅雷页面后任务监控停止**
任务监控只读复用迅雷页面的前端状态，不会主动重开页面；重新打开并再次发送即可恢复监控。

## 手动测试清单

需要真实 NAS 环境验证；任务监控部分建议准备一条可快速完成的小文件链接，以及一条会失败的链接。

**基础与发送**

- [ ] 设置页：空地址/非 http(s) 地址保存时有警告；合法地址保存成功
- [ ] 设置页：「打开迅雷页面」能打开/聚焦所配地址
- [ ] 未配置地址时：右键菜单/popup 发送有明确提示
- [ ] 立即下载模式：右键发送一个磁力链接 → 任务出现在 NAS，默认只弹失败通知、不弹成功通知
- [ ] 确认后下载模式：右键发送 → 迅雷页面停在确认框，可编辑文件名/路径后手动确认
- [ ] 默认下载位置：配置一个已存在且可写的目录（如 `/downloads/02`）→ 立即下载 → 通知/记录显示保存路径，迅雷任务详情一致
- [ ] 默认下载位置：配置不存在的目录 → 通知说明原因，任务仍按迅雷当前目录下载
- [ ] 确认后下载模式：路径已预选在迅雷确认框中，仍可手动改路径
- [ ] popup 多行/空格分隔链接、重复链接、非链接文本、超过 50 个链接时的计数与提示
- [ ] popup Ctrl / ⌘ + Enter 发送
- [ ] 右键选中文本（含多个链接）、视频/音频元素、无链接选区
- [ ] popup 与右键同时发送：第二个提示“正在发送中”，不重复建任务
- [ ] 关闭「发送前刷新」且迅雷页有残留结果框时，发送被拦截并提示先处理

**诊断与通知**

- [ ] 设置页「测试连接」：正确地址全部通过；错误地址/离线地址、未登录、非迅雷页面分别给出对应原因
- [ ] 设置页「从迅雷选择」：根目录加载、展开子目录、选择并保存路径
- [ ] 发送失败通知：按钮「打开设置/打开迅雷」「重试」可用；点击通知正文能直达对应页面
- [ ] 成功通知开关：默认关闭；开启后发送成功会弹通知
- [ ] 路径未生效通知：配置不可写/不存在的目录时触发，可打开设置或迅雷
- [ ] 通知重试：停止 Service Worker 后点击「重试」仍可用；超过 30 分钟后提示记录过期
- [ ] 发送记录：显示时间、链接数、模式、消息、监控摘要；失败可重试；可清空
- [ ] 首次安装/清空地址后打开设置页能看到三步引导

**番号匹配**

- [ ] 配置页：自动识别/手动补充/类型/大小/关键词/上限/排序保存后重载一致；恢复默认只重置番号匹配
- [ ] 规则预览：默认示例中 ABC-123 命中、ABC-1234 不命中、sample/图片/文本排除；粘贴文件名和选择本地文件夹（如 `Z:\xfmovie`）只读预览
- [ ] 只读读取当前迅雷弹窗：解析磁力后能读到任务/文件/大小/勾选状态；无弹窗有提示；不创建任务
- [ ] 确认后下载 + 自动识别：目标正片被勾选，sample/图片/文本不勾选，停在弹窗不自动点击
- [ ] 立即下载 + 全部匹配：只点击一次，任务创建成功
- [ ] 严格未匹配：普通非番号磁力不点击、弹窗保留、通知「已暂停」、记录状态「已暂停」、不启动监控
- [ ] 回退模式：未匹配任务保留原勾选并继续，记录/消息标注回退
- [ ] 类型/大小/关键词/每任务上限 + 排序实际生效；多任务部分未匹配时严格整单暂停
- [ ] 非 BT 直链跳过匹配正常发送；关闭总开关后行为与旧版一致
- [ ] 迅雷组件能力异常/文件树超时：严格暂停不点击，回退按原勾选继续

**接口直连通道（含番号匹配）**

- [ ] 切到「接口直连」后发送磁力：迅雷页面**不打开、不抢焦点**，任务出现在 popup 任务页
- [ ] 立即下载 + 番号匹配：只有目标正片被下载，`sub_file_index` 与页面自动化结果一致（可用 NAS 上任务的详情核对）
- [ ] 严格未匹配：该链接不建任务、通知「已暂停」，**同批其它已匹配链接仍正常创建**
- [ ] 回退模式：未匹配链接整包下发（不传 `sub_file_index`），记录/消息标注
- [ ] 手动番号 / 类型 / 大小 / 关键词 / 上限 + 排序：与页面自动化模式给出相同选择
- [ ] 分集/文件夹包：中间层目录名带番号时按整体保留，得到 `"0-1"` 这类连续段
- [ ] 保存路径：配置的路径解析成 NAS 目录；路径不存在时回退迅雷默认目录并如实提示
- [ ] 非 BT 直链跳过匹配正常发送；关闭番号匹配总开关后整包下发
- [ ] 令牌过期/迅雷升级取不到令牌：明确报错并提示切回页面自动化，不静默失败
- [ ] popup 任务页：进度/速度实时刷新，暂停、继续、删除（含二次确认）生效

**任务监控**

- [ ] 立即下载：发送小文件 → 记录出现“监控中” → 完成后记录更新；完成通知默认不弹
- [ ] 下载失败链接：任务进入 ERROR → 失败通知包含任务名，记录失败数更新
- [ ] 开启“下载完成通知”后，完成任务会弹通知
- [ ] 批量 3-5 个链接：同一轮扫描的失败/完成合并成一条通知，不刷屏
- [ ] 确认后下载：发送后等待 2 分钟再点「立即下载」→ 监控仍能发现并跟踪任务
- [ ] 监控中关闭迅雷页面：约 3 分钟后记录显示“监控停止：迅雷页面已关闭”，不弹失败通知
- [ ] 关闭「下载任务监控」后，发送不再产生监控记录/任务通知

## 已知限制

- **默认下载位置只支持已存在的目录**：插件按迅雷面板显示的路径逐级查找目录并预选，不会自动创建目录；路径不存在、不在可下载目录范围内或不可写时，会回退到迅雷当前目录并在通知中说明原因。「确认后下载」模式仍可手动选择路径。
- **任务监控依赖迅雷页面保持打开**：插件不会主动重开页面；页面关闭、连续读取失败、离开配置地址或超过 24 小时后停止监控，并在发送记录中写明原因。浏览器休眠、页面被冻结时监控可能延迟。
- **任务监控依赖迅雷 Vuex 状态**：读取 `drive.all/tasks/tasksDone` 并复用面板自身的 `drive/getTask`；迅雷大版本更新若改动该结构，需要适配 [utils/xunleiAutomation.ts](utils/xunleiAutomation.ts)。任务错误详情可能无法读取，此时只保证失败状态和任务名。
- **路径预选依赖迅雷面板的前端状态**（Vuex 中的 `treeNodeId/treeNodePath`）；迅雷大版本更新若改动该结构，需要适配 [utils/xunleiAutomation.ts](utils/xunleiAutomation.ts)。
- **番号匹配依赖迅雷文件树组件**：通过页面 Vue 组件的 `setCheckedKeys` 应用勾选；迅雷大版本更新若改动组件结构/方法名，会暂停并提示手动处理，不会在不确认的情况下点击下载。匹配逻辑只用 xeyes 的文件名规则做本地识别，不引入模型、不请求外部服务。
- **番号匹配排序不改变迅雷界面**：仅用于选择保留哪些文件；设置每任务上限可能漏掉分集，默认 0（不限）。
- **番号匹配只处理 BT 文件树**：直链任务跳过；页面自动化模式下多任务严格模式整单暂停（接口直连按链接独立暂停）。手动番号/关键词仅保存在本机 `storage.local`，历史只记录计数和少量摘要，不保存完整文件列表。
- **接口直连依赖套件私有接口**：`drive/v1` 契约从 [cnk3x/xunlei](https://github.com/cnk3x/xunlei) 的群晖套件中逆向确认（实测 v3.23.5；上游已发布 4.0.0-beta，接口可能变化），迅雷大版本更新可能改变首页令牌或字段；取不到令牌或接口报错时会明确失败并提示切回页面自动化，不会在不确认的情况下继续建任务。
- **接口直连不启动页面任务监控**：该通道不打开迅雷页面，因此原有的每分钟任务监控不生效，下载状态请直接在 popup「下载任务」页查看；通知仍覆盖发送结果与番号匹配暂停。
- **接口直连没有「确认后下载」**：接口层没有迅雷确认框，任务一律直接开始；需要人工确认文件名或路径时请用页面自动化通道。
- **DOM 自动化依赖 [cnk3x/xunlei](https://github.com/cnk3x/xunlei) 的页面结构**，迅雷或套件大版本更新后选择器可能需要适配。
- **通知按钮/常驻显示是尽力而为**：不同平台支持度不同；即使按钮不可用，popup 内联结果和发送记录仍保留完整信息。
- **不自动重试点击步骤**：新建任务、填链接、点击立即下载都有副作用，自动重试可能重复建任务；请使用失败通知/记录里的「重试」整链重跑。
- **发送记录保存在本机**：包含链接文本，提供清空按钮，不跨设备同步。
